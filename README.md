# y2-pycov — coverage tooling

The single coverage base for the parent project. Provides context-aware coverage analysis with per-test attribution to support coverage-quality workflows (e.g., identifying redundant or useless tests).

## End-to-end usage: Find useless tests (0-unique-line candidates)

The full workflow to identify tests that cover no unique lines (every line they cover is also covered by at least one other test):

### 1. Generate extended coverage with per-test contexts
```bash
python y2-pycov/create_extended_coverage.py
```

This runs:
- Coverage configuration with `dynamic_context = test_function` (REQUIRED for per-test tracking)
- Full test suite: `tests/` and `knowledge_tool/knowledge_tool/tests/`
- Writes isolated `.coverage` data file to `y2-pycov/.coverage` (not the project root)
- Automatically runs `coverage_report.py` on the generated data

**Important:** Use the FULL suite for accurate uniqueness measurement. Running only a subset of tests makes everything look 0-unique because uniqueness is measured against ALL tests.

### 2. Emit per-module attribution report
```bash
python y2-pycov/coverage_report.py --data-file=y2-pycov/.coverage
```

Outputs JSON mapping each executed line to the tests that hit it:
```json
{
  "modules": [
    {
      "file": "knowledge_tool/module.py",
      "covered_lines": 45,
      "tests_by_line": {
        "10": ["test.test_foo", "test.test_bar"],
        "11": ["test.test_foo"]
      }
    }
  ]
}
```

### 3. Identify 0-unique-line candidates
For each test, count lines it covers that **it alone** covers (unique_line_count):
- Lines covered by exactly 1 test = that test's unique contribution to coverage
- Tests with unique_line_count == 0 = every line they execute is also executed by other tests
- These are **coverage-redundant** (but NOT necessarily test-redundant; the test may still exercise important assertions or edge cases)

Example algorithm:
```python
test_to_lines = {}  # test -> set of (file, lineno) it covers
for test in all_tests:
    unique_count = 0
    for (file, lineno) in test_to_lines[test]:
        # If this test is the ONLY one covering this line
        if len(tests_covering(file, lineno)) == 1:
            unique_count += 1
    if unique_count == 0:
        candidates.append(test)  # 0-unique-line candidate
```

### 4. SURFACE for human review (recommend, never auto-delete)
The plugin's `find_useless_tests` playbook performs steps 1-3 and surfaces candidates for human review. **Coverage redundancy ≠ test redundancy** — a test may have 0 unique lines but still exercise critical assertions, dependencies, or edge cases. Always review before deleting.

## Technical details

### Gotchas and scoping

- **dynamic_context required:** Coverage tracking is disabled without `dynamic_context = test_function` in the coverage config. The config is auto-generated by `create_extended_coverage.py`.
- **Absolute paths stored:** Coverage `.coverage` data stores absolute file paths. Use `coverage_report.py --data-file=y2-pycov/.coverage` (not hand-queries) to get relative paths.
- **Isolated .coverage in y2-pycov/:** The extended coverage data lives at `y2-pycov/.coverage`, not the project root. This avoids polluting the project and keeps the plugin's coverage analysis self-contained.
- **Full suite for uniqueness:** Measure uniqueness against the FULL test suite (both roots). Partial runs distort the metrics.
- **Plugin-internal only:** Coverage analysis and useless-test identification are plugin-specific (evaluates own test quality). The playbook does NOT propagate to user projects.

### Importability note
This directory is hyphenated (`y2-pycov`), so it cannot be imported by package name. External callers load modules by file path via `importlib.util.spec_from_file_location`. This loads the file directly and does **not** mutate `sys.path` — no `sys.path` hacks anywhere.

## Components

### `coverage_tools.py` — the analysis engine
Generic context-aware coverage analysis built on the `coverage` package's
`CoverageData`. Its APIs accept arbitrary context labels and data-file paths:
- `discover_tests_ranked(data_file)` — every test ranked by the number of lines it covers.
- `cov_lines_by_test(test_name, base_dir, data_file)` — the files/lines a single test covers (relative paths).
- `extended_cov_lines_raw_structure(filepath, base_dir, data_file)` — per-line test contexts for a file (`{lineno: [test_ctx, ...]}`).
- `load_coverage_matrix` / `rank_tests_by_line_count` — the underlying primitives.
- `export_coverage_context(data_file, context, output_file)` — copy one arbitrary context to an independent coverage database.

### `coverage_report.py` — token-efficient per-module JSON report
Built **on top of** `coverage_tools.py` (it calls `extended_cov_lines_raw_structure`).
Emits a flat, machine-readable, per-module JSON report, filterable by module
substring — cheap to consume vs. an HTML coverage blob.

```bash
python y2-pycov/coverage_report.py                          # full JSON report
python y2-pycov/coverage_report.py --module tasks.py        # filter to module(s)
python y2-pycov/coverage_report.py --compact                # single-line JSON
```

`build_report(data_file, base_dir, module_filters)` is the programmatic API.

### `create_extended_coverage.py` — coverage generation CLI
High-level driver that generates extended coverage data with per-test contexts. Wraps the coverage and pytest commands with proper configuration and isolation.

```bash
python y2-pycov/create_extended_coverage.py  # generates y2-pycov/.coverage + runs report
```

## `mcp_coverage_server.py` — optional MCP server
Wraps the engine as FastMCP tools (`discover_tests`, `cov_lines_by_test`,
`extended_cov_lines`). Requires the **optional** `fastmcp` dependency; the report
path above does NOT need it, and `test_mcp_coverage_server.py` is kept off the
parent project's pytest `testpaths` so the suite runs without `fastmcp`.

## Importability
This directory is hyphenated (`y2-pycov`), so it cannot be imported by package
name. External callers (and `coverage_report.py` loading its sibling
`coverage_tools.py`) load modules by file path via
`importlib.util.spec_from_file_location`. This loads the file directly and does
**not** mutate `sys.path` — no `sys.path` hacks anywhere.

## Coverage data
Uses the project `.coverage` data file.
